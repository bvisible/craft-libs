# Neoffice fork markers

Map of **our** divergence from upstream (`storytold/craft-libs`) in this fork (`bvisible/craft-libs`,
branch `version-15`). Everything that can carry a comment carries a `//// Neoffice — …` marker in
place: `// //// Neoffice — …` in Rust (a bare `////` is an error for clippy), `# //// Neoffice — …`
in TOML and YAML, `<!-- //// Neoffice — … -->` in Markdown. This file holds what cannot.

At the next upstream merge, `grep -rn "////"` in the source plus this file give the complete
picture of what is ours and why.

## Base of the divergence

Last upstream merge: `storytold/craft-libs` `main` at `c6db9e8` (2026-11-12, 824 commits after the previous base
`ea1fbeb` of 2026-11-02). `git merge-base HEAD upstream/main` gives the base the marker check (CI "Neoffice fork
markers") compares against. That merge changed none of upstream's code and none of ours: the workspace stays on egui 0.37
(on upstream's own `[patch]` of the storytold egui fork, same revision), and upstream's moves of the previous weeks touch
neither crate of ours (`craft_update::install_package` gained a `bundle` parameter and `craft_text`'s `Dictionary::to_bytes`
returns a `Result`; our crates call neither). Three files conflicted, each because both sides appended to the same place:
`Cargo.toml` (our two workspace dependency lines kept beside upstream's new crates), `README.md` (our two crate entries
kept beside upstream's new ones) and `Cargo.lock` (upstream's taken, then `cargo check` wrote our two entries back).
Upstream's README lists `craft-mesh` with a duplicated line (a defect of theirs, left as it came).

## What the fork adds

Two crates, shared by every Neoffice editor (decision of 2026-10-13): `craft-nora`, the client core
of Nora, the Neoffice assistant (sans I/O: protocol, conversation state machine, document actions),
and `craft-nora-ui`, its egui panel. No upstream code was changed, apart from the two lines that
register them in the root `Cargo.toml` and the two lines that list them in `README.md`. They use
nothing else of this workspace, except upstream's `craft-ai-core`, which `craft-nora` reads behind its
`ai-core` feature (Nora's errors and turns in the vocabulary the Craft apps share for AI jobs, 17.10).

## 2026-11-05: the pane takes the design system's look, dictation, and a faster read

`craft-nora-ui` draws the Neoffice design system (palette light and dark, Karla and Forum, Lucide icons, Nora's sphere):
`look.rs`, `icons.rs`, `orb.rs`, `orb_rings.rs` (generated by `tools/gen_orb.py`), `fonts/`, and a microphone (`voice.rs`).
`craft-nora` learns what Nora is doing (`Activity`), turns a recording into words (`Input::Transcribe`, `Dictation`,
`protocol::STT_TRANSCRIBE`) and reads its replies and actions often right after something happened in the turn, not only in
its first fifteen seconds. The panel now needs egui 0.37 (it names widgets by their accesskit `Role`). Upstream's files touched:
`ATTRIBUTION.md` (rows for the fonts, the icons and the sphere) and `Cargo.lock` (the browser crates of the microphone).

## 2026-11-12: `craft-proof` carries French, for builds that read no folder and download nothing

Upstream's French is a Language pack that the app downloads; a build that runs in a browser can neither read a folder nor download. The fork
changes `crates/proof` so that a program can hand a dictionary over in memory, and brings back the French behaviour the fork had measured
(`bvisible/wordcraft` embeds Grammalecte 7.7 and registers it at start-up). Everything here is generic (no Neoffice-specific code or text):
each change is its own commit, marked `//// Neoffice`, and can be proposed upstream as it stands once the marker lines are taken out.

- `embedded.rs` (added file): `embed_dictionary(tag, label, aff, dic, Packing)` registers the `.aff` and `.dic` bytes of a language, plain or raw
  DEFLATE; nothing is parsed before the first check and the regions of a language (`fr-FR`, `fr-CH`) share one parsed dictionary.
  `pack_lang.rs` chooses the source: the user's dictionaries folders, then the embedded dictionary, then installed packs and the system's
  (an unreadable folder file leaves its reason and the embedded one serves); one thread reads a dictionary at a time.
- `affix.rs`: a prefix's continuation classes license suffixes (`watts`: `watt/Um` and `PFX Um 0 0/S.`); a word in capitals with an apostrophe is the
  elided form of a capitalized stem (`L'ALLEMAGNE`); a `KEEPCASE` homonym no longer locks the stem's other homonyms (`Bit`, `Bar`, `Pi`); `adds_prefix` and
  `elisions` read the elisions a dictionary writes as prefixes.
- `pack_lang.rs`: a unit's exponent (`km²`) and an elision before an acronym or the user's word (`l'OTAN`, `d'Apple`) are not mistakes.
- `pack_suggest.rs` (added file): suggestions for a pack language with the first letter dearer to change, an elision of a word to correct
  (`dacord`) and the wrong part of a hyphenated word (`parle-t-ill`).
- `fr_grammar.rs` (added file) and `lang.rs`/`lib.rs`: French repeated-word and spacing checks with French messages; `fra` and `fre` are French.

Upstream's tests that take `fr-FR` for a language with no dictionary fail on a machine that has a system French dictionary (the engine now reads
the Mac's `fr-FR`); they pass on CI and with an empty `HOME`.
